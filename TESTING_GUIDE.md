# Руководство по тестированию исправления краша HTTP

## Цель тестирования
Убедиться, что приложение не вылетает при подключении к камерам без доступного HTTP порта.

## Сценарии тестирования

### Тест 1: Камера с недоступным HTTP портом
**Цель**: Проверить, что приложение не крашится при недоступном HTTP порте

**Шаги**:
1. Откройте приложение
2. Добавьте новую камеру со следующими параметрами:
   - IP адрес: `192.168.1.XXX` (реальный IP вашей камеры)
   - RTSP порт: `554` (доступный)
   - HTTP порт: `80` (недоступный)
   - PTZ порт: `8080` (доступный)
   - Логин и пароль: (ваши учетные данные)
3. Попробуйте подключиться к камере

**Ожидаемый результат**:
- ✅ Приложение НЕ должно вылететь
- ✅ RTSP видео должно воспроизводиться (если RTSP порт доступен)
- ⚠️ HTTP-зависимые функции могут не работать (PTZ через HTTP, снимки)
- ✅ Приложение должно показать сообщение об ошибке, но продолжить работу

### Тест 2: Автоопределение протокола PTZ
**Цель**: Проверить, что автоопределение не крашится при недоступном HTTP

**Шаги**:
1. В окне редактирования камеры нажмите "Автоопределение PTZ протокола"
2. Дождитесь результата

**Ожидаемый результат**:
- ✅ Приложение НЕ должно вылететь
- ✅ Должно отобразиться сообщение о невозможности определить протокол
- ✅ Можно продолжить использование приложения

### Тест 3: Проверка авторизации
**Цель**: Проверить, что проверка HTTP авторизации не крашится

**Шаги**:
1. В окне редактирования камеры нажмите "Проверить авторизацию"
2. Дождитесь результата

**Ожидаемый результат**:
- ✅ Приложение НЕ должно вылететь
- ✅ Должно отобразиться сообщение об ошибке подключения
- ✅ Можно продолжить использование приложения

### Тест 4: Захват снимка
**Цель**: Проверить, что захват снимка через HTTP не крашится

**Шаги**:
1. Откройте камеру с недоступным HTTP портом
2. Попробуйте сделать снимок (если такая функция есть в UI)

**Ожидаемый результат**:
- ✅ Приложение НЕ должно вылететь
- ⚠️ Снимок может не получиться (это нормально)
- ✅ Приложение должно корректно обработать ошибку

### Тест 5: Камера с доступным HTTP портом (регрессионный тест)
**Цель**: Убедиться, что исправление не сломало работу с нормальными камерами

**Шаги**:
1. Добавьте камеру с доступным HTTP портом
2. Проверьте все функции: видео, PTZ, снимки, авторизацию

**Ожидаемый результат**:
- ✅ Все функции работают как раньше
- ✅ HTTP запросы проходят успешно
- ✅ PTZ управление работает
- ✅ Снимки захватываются

## Проверка логов

Если приложение подключено к Android Studio, проверьте логи на наличие:

```
W/CameraHttp: HTTP порт недоступен: Connection refused
W/PtzProtocolDetector: HTTP probe http://... failed: HTTP порт недоступен
```

Это нормальные предупреждения, указывающие на недоступность HTTP порта.

## Критерии успеха

✅ **PASS**: Приложение не вылетает ни в одном из тестов
✅ **PASS**: Ошибки обрабатываются корректно с понятными сообщениями
✅ **PASS**: RTSP видео работает даже при недоступном HTTP
✅ **PASS**: Камеры с доступным HTTP продолжают работать нормально

❌ **FAIL**: Приложение вылетает (показывает "app has stopped")
❌ **FAIL**: Белый экран или зависание
❌ **FAIL**: Невозможно использовать камеры с доступным HTTP
